# Модель always-on в road-map-journal

Как работа без присмотра в road-map-journal соотносится с моделью из статьи Anthropic [Building always-on agents](https://claude.com/resources/articles/building-always-on-agents) (13.11.2026), что мы переносим и что сознательно делаем иначе. Составлено 15.11.2026 по итогам сравнения и независимого ревью; изменения — ревизия планирования от 2026-11-15 в [ROADMAP.md](../ROADMAP.md). Полная версия на английском: [always-on-model.md](always-on-model.md).

Это карта, а не обещание: у каждой строки указано, **реализовано** это или **запланировано** (с пунктом ROADMAP). Запланированное не разрешает что-либо строить или запускать.

## Цикл

«Всегда включённый» агент не работает постоянно: он спит, просыпается, выполняет один короткий **запуск**, записывает результат и снова засыпает. Сон не тратит токены модели.

- **Пробуждение:** системный таймер запускает `roadctl tick` (реализовано), позже conductor `roadctl serve --once` (P5.25); мост может запустить его сразу после записи ответа или запроса владельца (P5.25).
- **Решение без модели:** `tick` читает доски, находит работу, проверяет лимиты подписки и резерв владельца; модель стартует, только если есть работа и резерв позволяет (реализовано). В статье этого шага нет.
- **Запуск:** один ограниченный запуск под `roadctl supervise` (реализовано, P5.2).
- **Запись:** Log, Handoff и Evidence карточки в git, сводка `routine done` / `report`, локальный журнал запусков (реализовано).

## Пять примитивов

| Примитив | road-map-journal | Состояние |
| --- | --- | --- |
| **Inbox** | работа вычисляется из доски в git; ответы и запросы владельца попадают на доску (P5.24, P5.36); записи из канала идемпотентны по id канала | вычисление реализовано, остальное запланировано |
| **Один исполнитель** | блокировки `tick` и `supervise`, heartbeat, поиск осиротевших запусков, back-off; conductor выполняет действия по одному (P5.25) | реализовано; conductor запланирован |
| **Таймеры** | `every` и `hours` рутин, истечение аренды (`STALE`), дедлайны запусков; вычисляются при чтении; разовая дата перепроверки — идея (P5.37); работа по карточкам идёт фиксированными сменами с равномерной долей лимита (P5.39) | реализовано; P5.39 запланировано; P5.37 — идея |
| **Память** | инструкции: мандат (P5.33), файл рутины с хешем подтверждения (P5.15); прогресс: Handoff, checkpoint, Log в git; что уже сказано: `digest.state.json`; предпочтения владельца — идея (P5.38) | частично; P5.38 — идея |
| **Права** | команды только для владельца, области `read+board` / `external`, хеш подтверждения, уровни L1–L4, unattended-режим (P5.3); вопрос блокирует только карточку (P5.24); правила для секретов (P5.19, P5.7) | частично реализовано |
| **Outbox** | `roadctl digest`: по умолчанию только проблемы, каждая один раз, ежедневный обзор; подтверждённая доставка в две фазы (`digest --json` с токеном, затем `digest --ack`) для моста (P5.26) | реализовано; подтверждение запланировано |

## Сознательно не переносим

- Классификаторы прав (auto mode): права — детерминированные правила и решения владельца.
- Подмешивание события в идущий запуск или его прерывание: событие ждёт следующего запуска, прерывает только `pause --now`.
- Автоматический повтор события после сбоя: неизвестный исход не повторяется.
- Отдельное хранилище таймеров, из которого планировщик переносит события в inbox.
- Продолжение сессии как основа работы: основа — checkpoint и Handoff.
- Память, которую агент пишет без подтверждения владельца; хранение текста отправленных сообщений.

## Секреты

Никогда в git, на доске, в промпте, файле рутины, реестре, журнале запусков, логах запусков и digest. Токены только для чтения с минимальными правами могут быть на машине рутины. Токены с правом записи — вне среды агента; это условие для области `external` (P5.19). Описание запуска печатает только имена переменных (P5.7).
