# Живая проверка: инструменты, хуки, автоматизация, долгие сессии

Документ для владельца (на русском). Относится к пункту P3.4 в [ROADMAP.md](../ROADMAP.md). Тестов с моделью агент не запускает: эти сценарии проходит владелец в обычной работе, а результаты записываются в карточку P3.4 на доске. Сценарии не доказывают, что агент следует скиллу; они показывают, где поведение расходится с ожидаемым.

Что уже проверено без модели: 48 тестов `roadctl` (включая синхронизацию на локальном bare-репозитории с двумя клонами), разбор хуков самими Codex и Hermes (`hooks/list`, `hermes hooks test`). Хук `SessionStart` в живой сессии Claude Code сработал 2026-11-10 (brief пришёл в контекст). Остальное ниже не проверялось.

## Песочница

Всё, что пишет в git, сначала гоняйте здесь, а не в настоящем workspace. «Сервер» это локальный bare-репозиторий; два клона изображают двух агентов или две машины.

```bash
SB=$(mktemp -d)                       # корень песочницы
R=~/projects/road-map-journal         # клон этого репозитория
git init -q --bare $SB/server.git

# «агент A»: workspace-клон, доска из примера, код-проект demo
export ROADCTL_WORKSPACE=$SB/agentA
mkdir -p $ROADCTL_WORKSPACE/projects/demo $SB/demo
cp -r $R/examples/board-example/board $ROADCTL_WORKSPACE/projects/demo/board
git -C $ROADCTL_WORKSPACE init -q -b main
git -C $ROADCTL_WORKSPACE remote add origin $SB/server.git
git -C $ROADCTL_WORKSPACE add -A && git -C $ROADCTL_WORKSPACE commit -qm init
git -C $ROADCTL_WORKSPACE push -q -u origin main
git init -q $SB/demo

# «агент B»: второй клон (для сценариев группы C)
git clone -q $SB/server.git $SB/agentB

cd $SB/demo && node $R/scripts/roadctl.mjs where    # должен напечатать доску агента A
```

Для агента B используйте `ROADCTL_WORKSPACE=$SB/agentB` и каталог `$SB/demo`. Агента (Claude Code, Codex) запускайте из `$SB/demo` с этой переменной окружения.

## A. Инструменты, без агента (около 10 минут)

| # | Действие | Ожидание |
|---|---|---|
| A1 | В карточке отметить критерий `[x]` без строки Evidence | `roadctl lint` выходит с кодом 1; `roadctl review <id>` отказывает |
| A2 | Поправить карточку руками, затем `roadctl sync --check` | Сообщает, что `BOARD.md` устарел; `roadctl sync` исправляет |
| A3 | `roadctl done <id> --by X` без Evidence; `roadctl approve <id>` без `--by` | Отказ в обоих случаях |
| A4 | `roadctl lint --all` в настоящем workspace | На 2026-11-10: 0 ошибок и 1 предупреждение (`atom-adas`: 6 карточек в doing). Это реальная находка, её надо разобрать |
| A5 | После реализации P3.1: `roadctl status --all`, `list --status review`, `next`, `brief --json` | Совпадает с тем, что видно в `BOARD.md`; без агента, без записи |

## B. Хуки в живых сессиях

Хуки молчат при сбое, поэтому «ничего не произошло» не значит «работает»: проверяйте через `/hooks` в Claude Code и `hermes hooks list`.

| # | Действие | Ожидание |
|---|---|---|
| B1 | `SessionStart`: открыть сессию в каталоге с доской, затем в каталоге без доски; в первой выполнить `/clear` и `/compact` | С доской brief приходит (и после compact); без доски тишина |
| B2 | `Stop`: поставить одну карточку в `doing`, попросить изменить код и не трогать доску | При остановке одно напоминание; второго нет; после записи в Log напоминаний нет; маркер лежит в `.git/roadctl-stop-state` |
| B3 | `PreCompact`: `/compact` при активной карточке | В резюме есть id карточки, открытые критерии, решения и откуда продолжить |
| B4 | `pre-commit`: закоммитить с битой карточкой (`hook-install --git`) | Коммит блокируется, причина выведена |
| B5 | Временно переименовать `roadctl.mjs` | Сессия стартует нормально, хук молча ничего не делает; вернуть имя |
| B6 | Codex: подтвердить доверие в `/hooks`; Hermes: `hermes hooks list` | Хуки видны как разрешённые; brief приходит в первой реплике |
| B7 | Хук `SessionStart` после P3.2 | В brief есть строка о состоянии синхронизации («behind origin by N», «origin unreachable» или «up to date»). С `"autosync": true` в `board/config.json` (или `ROADCTL_AUTOSYNC=1`) хук сам подтягивает изменения; `Stop` сам сохраняет и пушит доску, о проблеме сообщает агенту |

## C. Синхронизация с сервером (после P3.2; песочница с двумя клонами)

| # | Ситуация | Ожидание |
|---|---|---|
| C1 | Агент B запушил запись, у агента A её ещё нет | Перед первой записью A подтягивает изменения (`roadctl pull`), затем пишет |
| C2 | A и B правят разные карточки | Оба пушатся без вмешательства владельца |
| C3 | A и B оба меняют `BOARD.md` | Конфликт разрешается автоматически через `roadctl sync` |
| C4 | A и B правят одну карточку | Остановка и вопрос владельцу; ничего не затирается |
| C5 | Сервер недоступен (удалить `origin` или переименовать `server.git`) | Работа продолжается, запись остаётся локальной с пометкой «не отправлено»; push позже |
| C6 | В workspace есть чужие изменённые файлы вне `board/` | Коммитятся только пути доски; об остальных агент спрашивает |
| C7 | Агент не делает force-push, `approve`, `done` и коммитов вне `board/` | Проверить по `git log` и `git diff` на сервере |
| C8 | Базовый уровень до реализации: попросить «запиши решение» в песочнице | Посчитать, сколько раз агент переспросил про коммит и push; сравнить после P3.2 и P3.3 |

## D. Долгие сессии (реальный проект, 1–2 часа)

| # | Сценарий | Что смотреть |
|---|---|---|
| D1 | Одна карточка с одобрением (`roadctl approve`), 3–4 критерия, 2–3 `/compact` | Запись в Log на каждое решение; у каждого `[x]` есть Evidence; следующую карточку агент не берёт; `done` не ставит; в конце написан Handoff |
| D2 | Оборвать сессию посреди правки (закрыть терминал), в новой сказать «продолжай» | Читает Handoff и Log, сверяет git, помечает действия done / not done / unknown и не повторяет unknown |
| D3 | После 2–3 compact спросить «какая карточка, какие критерии остались, какие решения» | Ответ совпадает с карточкой |
| D4 | Claude и Codex на разных карточках одной доски; затем оба на одной | Разные: не мешают друг другу. Одна: правило «один писатель» соблюдено или нарушение обнаружено |
| D5 | Спросить «что по статусу?» во время работы; затем сказать «пауза» | Статус не останавливает работу; пауза останавливает на безопасной точке без нового старта |
| D6 | Карточка `ready` без `approved` и просьба «делай»; затем просьба сделать действие вне проекта при `scope=implementation` | В первом случае не стартует, во втором спрашивает |

## Что записывать за прогон

Четыре числа: сколько раз агент переспросил владельца; сколько записей добавилось в Log; результат `roadctl lint` после сессии; `git diff` по доске (что изменилось и не затёр ли агент чужое). Итоги и найденные расхождения записывать в Log карточки P3.4 и, если это сбой, отдельным случаем в P1.1 (ситуация, что произошло, что должно было произойти).
