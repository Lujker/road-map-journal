# External runner contract

A scheduler is a launcher, not a second source of board policy. Configure **one launcher per agent** for a board; switch launchers manually, with the previous one stopped. Locks and the local ledger do not coordinate different machines or state directories. A second clone or machine is not a hot standby.

1. Run `roadctl tick --as AGENT --board DIR --json`. Start work only on exit 0 and only for the returned items. Exit 4 is idle, 5 busy, 6 paused, 1 reserve and 3 unknown limits: start nothing. Treat malformed output and other errors as no work. `RUN` belongs only to the routine's own agent. Pass the same board and agent throughout.
2. For a `RUN`, obtain its launch description with `roadctl routine launch ID --board DIR --json`. Respect its reasons and use its `supervise_argv` and `argv`; the launch description itself starts nothing. `supervise --routine ID --as AGENT --board DIR -- COMMAND ...` rechecks eligibility under its per-routine lock. Exit 5 means another run is active: do not start a duplicate. The command must finish with `roadctl routine done ID --as AGENT --result ok|escalated|failed "summary" --board DIR`. Check the outcome and any local-only publication; reconcile before repeating an uncertain run.
3. An external runner that does not use `supervise` must share its lock for the whole run, or use `roadctl run begin ID --as AGENT --board DIR` before starting and treat exit 5 as busy. Carry the returned run ID in `ROADCTL_RUN_ID` to the command and finish with `routine done`. Fail closed if the ledger is unavailable: `run begin` can warn and continue without recording. It does not supply supervision, timeouts or process cleanup. In particular an overdue unsupervised run may be marked crashed while still alive; do not restart it until its process is known to have stopped. See [supervisor limitations](roadctl.md#run-supervisor).

The per-agent tick lock only covers the tick itself, not the subsequent work. Keep the same machine state directory for cooperating local processes. For the supplied scheduler example see [supervised-routine.sh](../examples/scheduler/supervised-routine.sh); command details and exit codes are in [roadctl.md](roadctl.md).
