# Changelog

Skill versions follow `metadata.version` in `skills/road-map-journal/SKILL.md`. Behavior was not re-evaluated for any release; see [ROADMAP.md](ROADMAP.md).

## Unreleased

- Repository (not part of the installed skill): seams for the next stage of `roadctl` (P5.28), no format change (`VERSION` stays 0.5.0). Modules may give a reason why a routine would not run (`routine-reasons`, the same in `tick`, `routine list`, `digest` and lint rule 30), declare routine keys and card or routine sections, add a `tick` kind with its prompt and ledger count (`tick-items`), refuse a START (`start-admit`, lint rule 31) and count a state other than `done` as meeting `depends_on` (`dep-satisfied`). Commands carry an owner flag (`approve`, `auto`, `queue`, `done`, `pause`, `resume`; `help <command>` says "Owner only", docs list them in one line checked by the help test); `roadctl help unattended` explains what an agent may do without the owner. One state directory and one lock helper (`scripts/roadctl/state.mjs`) replace three self-made locks with the same lifetimes and close the race where two processes took over the same stale lock; a lone `roadctl.mjs` without its folder keeps the tick lock. Developer rules: the queue for shared files and "a new hook only when two cards use it".
- Skill: drafting, reviewing or improving a plan, a track or the rules for unattended work is a grilling interview (rounds of numbered questions, each with a recommendation): the `grilling` skill from `mattpocock/skills` (`/grill-me` for the owner), with `domain-modeling` (`/grill-with-docs`) when the plan must match a codebase; `grill-me` and `grill-with-docs` are owner-invoked wrappers, so agents call `grilling` directly; if missing, the skill recommends the install command and installs only with permission; if the owner declines, it interviews in the same spirit itself. Previously this applied only to a new plan and was optional.
- Repository (not part of the installed skill): `roadctl` 0.5.0, run summary and delivery (P5.13; modules `scripts/roadctl/digest.mjs`, `run-summary.mjs`). `routine done`, `report` and the new `roadctl run done` (the duty orchestrator's own summary) take the fields `--did` (1 to 3, up to 120 characters), `--decision`, `--problem "transient|permanent|unknown: key: text"`, `--ask` and `--not-checked`, with limits; a Log line then has the form `did: a; b | decision: c | problem: kind: key: text | ask: q | not-checked: w [run=...]` (at most 1500 characters) that `roadctl digest` reads back, and the command prints the owner's summary (six lines at most, plain text). The old form (a text without fields) is unchanged. A new routine header key `notify: problems|always|never` (default `problems`) and a new `board/config.json` key `"summary": "required"` (refuses a run without `--did`). `roadctl digest [--since-state NAME] [--dry-run] [--all] [--json]` is model-free: problems, escalations, crashes and questions each once (the same problem key is not told twice, a gone problem is one `resolved` line), with the delivery state in the machine state directory; `roadctl digest --daily` is the overview, one line per enabled routine including OVERDUE ones (no run for twice `every` inside `hours`), the machine's crashed and skipped runs, an active pause (P5.5) and the owner's commands. Example Hermes `no_agent` job: `examples/scheduler/hermes-digest.py`. roadctl sends nothing itself; a delivery that fails after the text was printed loses that message (the daily overview is the safety net). **Format change:** a board that uses `notify` or `"summary": "required"` sets `"requires": "0.5.0"` (an older copy warns about the unknown key and reads the summary form as plain text); the `tick` RUN and TAKE prompts name the fields; `tick --json` is unchanged.
- Repository (not part of the installed skill): `roadctl pause [--reason TEXT] [--until SPAN|TIME] [--by NAME]`, `roadctl pause status [--json]` and `roadctl resume` (module `scripts/roadctl/pause.mjs`, P5.5): the owner's stop switch for one machine, in force at once and without git. One file, `pause.json`, in the machine state directory (WSL and native Windows have separate ones); no board, card or routine changes. While it exists `roadctl tick` starts nothing of any kind (TAKE, ACCEPT, START, STALE, RUN): it prints `tick AGENT: paused` and the reason (stable text, no clock), pulls nothing, asks no limits gate and exits with the new exit code **6** and the new decision `paused` (`tick --json`: `items` and `sync` empty, `limits` `not-checked`, plus a `pause` object; checker `scripts/testkit/tick-schema.mjs`). The ledger records one folded `paused` line and a `skipped` run with the reason `paused`. `status`, `routine list`, `tick --json` and `doctor` show an active pause; `--until` (a span like `4h` or a time with a zone) ends it by itself. A pause file that cannot be read counts as a pause. Compatibility: a scheduler that treats an unknown exit code as an error must handle 6, as the examples now do (`examples/scheduler/tick-claude.sh` stops quietly; the Hermes monitor scripts already keep the last prompt on any nonzero code, so no model is woken); a copy older than this change does not know the pause file and keeps running ticks. A run that has already started is not stopped (`pause --now` belongs to the supervisor card P5.2). Module seam: the named hook `pause-state`. `roadctl` `VERSION` is raised to 0.4.0 because the `tick` contract changed (a new decision and exit code); the pause itself is local machine state, not a card, routine or `config.json` format, so no board needs `requires` for it.
- Repository (not part of the installed skill): `roadctl doctor [--agent NAME] [--json] [--online [--host HOST]]` (module `scripts/roadctl/doctor.mjs`), a read-only check of the environment of one machine: version and checksum of the installed copy, its modules folder, Node and git, the registry and the command that starts an agent (looked up in `PATH` the way a non-interactive shell does), paths with their letter case, the state directory and a second one on WSL/Windows, `ROADCTL_*` against `WSLENV` and a `wsl.exe` probe (ssh with `--online --host`), clock against the newest fetched commit of origin, and per board `requires`, write access to the repository, uncommitted work and the consistency of routines. Warnings and failures are listed apart, `--json` has a documented schema (`scripts/testkit/doctor-schema.mjs`), environment variables are only named, exit 1 on a failure. `roadctl --version` prints `roadctl <version> sha:<12 hex>`; `update-installed.mjs --roadctl --apply` writes `installed.json` (version, sha, per-file sha) next to the installed copy. Changes nothing, starts no model, no network without `--online`. `VERSION` is not raised: no card, routine or config key and no existing output changed.
- Repository (not part of the installed skill): `roadctl` 0.3.0, the run ledger (P5.1). Every run of a routine and of a delegated task leaves a record in the machine state directory (`runs.jsonl`, never inside a git work tree; it holds the text of run summaries): start, end, outcome, reason, attempt and the (still empty) fields of a run summary. New: `roadctl runs [--open] [--json]`, `roadctl run begin|note` (hidden; a second `begin` answers exit 5), `claim` and `report` record the run of a task by themselves, `routine done` ends the run and, when the run is known, ends its Log line with ` [run=<id> dur=<s>s host=<host>]` (the other machine reads it from git), a run without an end after its deadline is marked `crashed` by the next `tick` (time threshold only), `tick` records `skipped` with the reason `busy`, `limits` or `not-due`, folds repeated `blocked-*` and `busy` ticks into one `ticks.jsonl` line with a counter in `ticks.state.json` and rotates the file inside `tick`. Format change: the routine header key `timeout` (after it an unfinished run counts as crashed; default 2h) and `attempt` in the `routine` of a `tick --json` RUN item (from 2, after a crashed or failed run; the text line ends with ` (attempt N)` so the monitor sees the change once). A board that uses `timeout` sets `"requires": "0.3.0"` in `board/config.json` first; an older copy only warns about the key and does not see `attempt`. Module seam: named hooks (`hooks` in a module, `HOOK_NAMES` in `scripts/roadctl/registry.mjs`), documented in `docs/developing-roadctl.md`. The test suites no longer write the real state directory.
- Repository (not part of the installed skill): `roadctl` 0.2.0 reads `requires` in `board/config.json` (`"requires": "0.3.0"`: the oldest roadctl that understands the board). A copy that is older, or cannot read the value, refuses that board: `roadctl tick` offers no item from it (no `RUN`, `TAKE`, `ACCEPT`, `START`, `STALE`) and prints one `requires: <project>: board requires roadctl <version> or newer; this is <version>` line (in `sync` for `--json`; the JSON shape and the decisions are unchanged, decision `idle`), `lint` reports rule 10, `routine list`/`show` and `brief` say why. Boards without `requires` behave exactly as before. `VERSION` is raised from 0.1.0 to 0.2.0 because this is a format change. Compatibility, in this order: (1) copies older than 0.2.0 do not know `requires` (they ignore the key in `config.json` and only warn about unknown header keys), so every machine that runs `tick` or routines must be updated to 0.2.0 or newer before the first card adds a header key; (2) from then on every change that adds a header key or a new meaning raises `VERSION` and the `requires` of the boards that use it; (3) new values are not added to existing fields (`last_result` stays `ok|escalated|failed`). Rules and the checklist for such cards are in `docs/developing-roadctl.md`; tests in `scripts/roadctl/requires.test.mjs`.
- Repository (not part of the installed skill): a test kit for the scheduler paths (`scripts/testkit/`: fake `claude`, `codex`, `ssh`, `hermes` and `wsl.exe` that record argv, environment and stdin and can succeed, hang, crash, print nothing or print a lot; a shared test clock; a checker for `tick --json` as a contract; a help-and-docs check; an optional private-marker scan driven by `ROADCTL_PRIVATE_MARKERS`).
