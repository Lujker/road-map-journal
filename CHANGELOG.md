# Changelog

Skill versions follow `metadata.version` in `skills/road-map-journal/SKILL.md`. Behavior was not re-evaluated for any release; see [ROADMAP.md](ROADMAP.md).

## Unreleased

- Repository: roadctl 0.13.0 adds owner questions (`ask`, `inbox`, `answer`, `undo`) with blocking and reversible decisions, checkpointed handoff, audit, routine answers and a versioned inbox contract. Boards using the format need `requires: 0.13.0`; see docs/roadctl.md.
- Repository: roadctl 0.12.0, the outcome policy and HOLD (P5.4). A routine stops running by itself after 3 consecutive `failed` runs (`escalated` does not count, `ok` resets the counter), after a run with scope `external` that ended without a result, or after an `aborted` run (timeout, `max_turns`, crash or stop): the `hold` header then keeps `tick` from offering a RUN until the owner runs `roadctl routine resume <id> --by NAME`. New routine header keys `last_reason` (the outcome detail: `ok`, `escalated`, `failed`, `transient`/`permanent`/`unknown`, `timeout`/`aborted`/`crashed`), `fails` (the consecutive-failure counter) and `hold`; `last_result` stays `ok|escalated|failed`. `routine done` (and the supervisor, `source=supervisor`) computes them; the hold reason comes through the `routine-reasons` hook of the new module `outcome-policy` (`tick`, `routine list`, `lint` rule 30 and `digest` agree); a hold is one episode with an id (`hold_id`), told once in `digest` as an immediate problem, again when it comes back after `resume`. The keys are outside the approval hash (P5.15) so a run never changes the hash. `skipped` does not change `last_result` or `fails`; a `limits` or `unreachable` skip (local run ledger) starts the term of `every` again, `not-due`, `busy` and `paused` do not. **Format change:** a board that uses `hold`, `fails` or `last_reason` sets `"requires": "0.12.0"`; roadctl writes these keys (and `hold_id`, the id of a hold episode) only on such a board, and a board without `requires` behaves as before.
- Repository: roadctl 0.12.0, limits polling after reset (P5.17): the limits cache records `closed_until` for a known reserve reset; `tick` does not poll before it. Limits account for the main provider only, including Hermes.

- Skill 0.4.1: clarify the 10% subscription reserve, checkpoint cadence and handoff before compaction. Behaviour was not re-evaluated in live agent sessions.
- Repository: `candidates --multiagent` is a static advisory only; it does not check availability, authorize or launch agents.
- Tests: wait for the detached supervisor's lock and guard before deleting its fixture, fixing the CI cleanup race.

- Repository: P5.43 building block `roadctl checkpoint CARD_ID --board DIR --as AGENT`, an explicit agent-supplied JSON handoff (`did`, `next`, `in_flight`) into the specified doing card's normal Log. Bounded input, mapped status and unique target checks; no automatic hook, status change, delivery or retry. No board format change or rollout.

- Repository: `roadctl limits` default reserve is now 10% in both subscription windows (weekly and five-hour; previously 15% in the five-hour window): the owner's permanent reserve, applied to every subscription provider (claude, codex and future ones) unless the registry's `limits.reserve` or a provider's own `reserve` overrides it key by key.
- Repository: `roadctl routine observe <id> --as AGENT [--confirm-after N] [--heartbeat DUR]` (P5.6, no format change, `VERSION` stays 0.11.0): the model-free close of a watchdog routine (`model: none`, script agent). JSON facts on stdin, stable problem keys, hysteresis, bad input is a failed `transient` run, the same publish path as `routine done`; `--heartbeat` keeps an unchanged run out of git (local `last_run` read by `tick`, `routine list` and `digest`). `tick` does not ask for limits when every item is a `model: none` RUN. Example: `examples/routines/watchdog.md`, `examples/scheduler/watchdog-example.py`. See docs/roadctl.md, Watchdog routine.
- Repository: roadctl 0.11.0, the early read-only slice of the planner (P5.34, module `scripts/roadctl/plan.mjs`). `roadctl plan check FILE [--json]` (hidden from the overview, described in docs/roadctl.md) checks one proposal file (JSON; the same format for a collaborative session, a future mandate run and a channel request) against the board and the mandate with no model, network, write or start: goal, a checkable criterion, a ROADMAP or mandate-goal link, the card limit, duplicates, dependencies and cycles, kind and size inside the mandate (outside it a valid proposal, not an error), form of a milestone section; the result is "proposed" or, only under an approved L3/L4 mandate and a fully defined card, "in-mandate"; missing, template or unknown env, role, effects, stop conditions and check methods never become permission. New optional mandate key `plan_max_cards` (default 5): an older copy would read it as an unknown key and the mandate as malformed (alerts and lint errors on every machine that runs it), so a board that sets it must also set `"requires": "0.11.0"` (lint rule 33 says so); older copies then refuse that board with one `requires:` line. Boards without the key are unchanged. No new card, routine or config key. Docs: [docs/plan-check-runbook.md](docs/plan-check-runbook.md) for the owner's live L2 scenario (a13); `plan apply`, inbox, milestones and the launcher are not built.
- Repository: roadctl 0.10.0, the work environment apart from the executor's machine (P5.23, module `scripts/roadctl/environment.mjs`). The registry may describe environments (`placement: local|remote-access`, the host and the access path); a RUN of a routine and a TAKE/ACCEPT/STALE delegation then carry `env` and `access` in `tick --json` (optional keys, checked by `scripts/testkit/tick-schema.mjs`). `roadctl env check ENV` (read only) says whether the environment is reachable (`ssh -o BatchMode=yes`); `supervise` makes the same check before the model starts and records `skipped: unreachable` (exit 4) instead of starting it. A host name that looks like an ssh option is refused. `roadctl candidates --card ID | --env NAME [--role R] [--needs ...]` (read only) shows the executor choice: the owner's preference list per role, confirmed fitness, tools and data, access path, the executor's own limits and budget; no candidate means nothing is launched. New card header keys `env`, `role`, `needs`: **format change**, a board that uses them or environments sets `"requires": "0.10.0"`. A registry without environments behaves as before. Docs: docs/roadctl.md, skill reference executors.md (Hermes is no longer the main path).

The JSON schema is `scripts/testkit/stats-schema.mjs`. No format change of a board and no change of `VERSION` (a new read-only command), so `requires` is unchanged; `digest.mjs` exports `boardEvents` and `loadBoards`, `mandate.mjs` exports `takes`.
- Repository: roadctl 0.9.0, permission boundaries part A (P5.3, module `scripts/roadctl/owner-gate.mjs`). Command entries carry `owner` (true, or `{ sub, flags }` for some calls, `ownerReads` for the reads of an owner command); in an unattended run (`ROADCTL_UNATTENDED`, or `ROADCTL_RUN_ID`) every owner call (`approve`, `done`, `auto`, `queue`, `pause`, `resume`, `mandate approve`, `routine on|off|resume|promote`, `autonomy on|off|routines`, `limits --confirm`, `boards add|remove`, the installers with `--apply`) is refused with exit code 1, and every owner call is one line (`time, command, target, by, outcome, via, run_id, unattended`) in `owner-commands.jsonl` of the machine state directory. `digest` tells a refusal at once (and, with the local setting `owner-gate.json` `{"bridge": NAME}`, an owner command not through the bridge) and the daily overview counts owner commands from git plus the local audit. On a board with an L3 or L4 mandate an unattended `claim`, `delegate`, `report`, `review`, `accept`, `return`, `undelegate` on a card outside the mandate is refused the same way. `lint` warns about broad permission rules in routine files (`Bash(roadctl:*)`, `Bash(git:*)`, a whole MCP server, a bare `Bash`, `Write` or `Edit` without a path). The gate is an agreement, not a sandbox. The mandate's own audit moved into the gate; no format change of a board, so `requires` is unchanged.
- Repository: roadctl 0.8.0, the project mandate and autonomy levels L1 to L4 (P5.33, module `scripts/roadctl/mandate.mjs`). One file `board/mandate.md` per board, approved by the owner as a whole by its content hash (the helper of P5.15; any edit, `## Goals` included, takes the approval away); `roadctl mandate [show|check] [--json]` reads, `roadctl mandate approve --by NAME [--hash H]` is owner only and refuses in an unattended run. At L3 and L4 with an approved mandate `tick` offers a START (`basis: mandate` in `--json`) for a ready card whose `kind`, `size`, `goal`, dependencies, Plan lines and budget are inside the limits, without `approved`, `auto` and the queue; `delegate` takes it and writes `by_mandate: <hash>` and a Log line; lint rule 6 accepts a current `by_mandate`; lint rule 33 reports a malformed or changed mandate and `digest` tells a changed one at once. New card keys `kind`, `size`, `goal`, `by_mandate`; new hooks `approval-basis` and `board-lint`. Compatibility: a board that uses a mandate sets `requires: 0.8.0`; an older copy (below 0.8.0) refuses the whole board, so it takes nothing by mandate and never sees a `doing` card without `approved`; a copy of 0.8.0 without the modules folder refuses it too. A board without `mandate.md` is unchanged. At L2 and below, with no mandate, or with an unapproved or changed one, `tick` output is the same as before. The limit of two ready milestones belongs with P5.35 (stage 3): until then an autonomous L3 is a training L3.

The prompt goes to stdin, never into argv. `roadctl launch --card ID --profile NAME` does the same for a card profile with an attempt limit, a card limit and a permitted strong profile; a later attempt gets only the measurable remainder and is refused while a run is live, its outcome is unknown or the remainder cannot be measured. `supervise` gets `--stdin` and `--model`; `doctor` checks the file. No board format changed, no `requires` needed; nothing is switched on without a local file.

- Repository (not part of the installed skill): `roadctl` 0.5.0, run summary and delivery (P5.13; modules `scripts/roadctl/digest.mjs`, `run-summary.mjs`). `routine done`, `report` and the new `roadctl run done` (the duty orchestrator's own summary) take the fields `--did` (1 to 3, up to 120 characters), `--decision`, `--problem "transient|permanent|unknown: key: text"`, `--ask` and `--not-checked`, with limits; a Log line then has the form `did: a; b | decision: c | problem: kind: key: text | ask: q | not-checked: w [run=...]` (at most 1500 characters) that `roadctl digest` reads back, and the command prints the owner's summary (six lines at most, plain text). The old form (a text without fields) is unchanged. A new routine header key `notify: problems|always|never` (default `problems`) and a new `board/config.json` key `"summary": "required"` (refuses a run without `--did`). `roadctl digest [--since-state NAME] [--dry-run] [--all] [--json]` is model-free: problems, escalations, crashes and questions each once (the same problem key is not told twice, a gone problem is one `resolved` line), with the delivery state in the machine state directory; `roadctl digest --daily` is the overview, one line per enabled routine including OVERDUE ones (no run for twice `every` inside `hours`), the machine's crashed and skipped runs, an active pause (P5.5) and the owner's commands. Example Hermes `no_agent` job: `examples/scheduler/hermes-digest.py`. roadctl sends nothing itself; a delivery that fails after the text was printed loses that message (the daily overview is the safety net). **Format change:** a board that uses `notify` or `"summary": "required"` sets `"requires": "0.5.0"` (an older copy warns about the unknown key and reads the summary form as plain text); the `tick` RUN and TAKE prompts name the fields; `tick --json` is unchanged.
- Repository (not part of the installed skill): `roadctl pause [--reason TEXT] [--until SPAN|TIME] [--by NAME]`, `roadctl pause status [--json]` and `roadctl resume` (module `scripts/roadctl/pause.mjs`, P5.5): the owner's stop switch for one machine, in force at once and without git. One file, `pause.json`, in the machine state directory (WSL and native Windows have separate ones); no board, card or routine changes. While it exists `roadctl tick` starts nothing of any kind (TAKE, ACCEPT, START, STALE, RUN): it prints `tick AGENT: paused` and the reason (stable text, no clock), pulls nothing, asks no limits gate and exits with the new exit code **6** and the new decision `paused` (`tick --json`: `items` and `sync` empty, `limits` `not-checked`, plus a `pause` object; checker `scripts/testkit/tick-schema.mjs`). The ledger records one folded `paused` line and a `skipped` run with the reason `paused`. `status`, `routine list`, `tick --json` and `doctor` show an active pause; `--until` (a span like `4h` or a time with a zone) ends it by itself. A pause file that cannot be read counts as a pause. Compatibility: a scheduler that treats an unknown exit code as an error must handle 6, as the examples now do (`examples/scheduler/tick-claude.sh` stops quietly; the Hermes monitor scripts already keep the last prompt on any nonzero code, so no model is woken); a copy older than this change does not know the pause file and keeps running ticks. A run that has already started is not stopped (`pause --now` belongs to the supervisor card P5.2). Module seam: the named hook `pause-state`. `roadctl` `VERSION` is raised to 0.4.0 because the `tick` contract changed (a new decision and exit code); the pause itself is local machine state, not a card, routine or `config.json` format, so no board needs `requires` for it.
- Repository (not part of the installed skill): `roadctl doctor [--agent NAME] [--json] [--online [--host HOST]]` (module `scripts/roadctl/doctor.mjs`), a read-only check of the environment of one machine: version and checksum of the installed copy, its modules folder, Node and git, the registry and the command that starts an agent (looked up in `PATH` the way a non-interactive shell does), paths with their letter case, the state directory and a second one on WSL/Windows, `ROADCTL_*` against `WSLENV` and a `wsl.exe` probe (ssh with `--online --host`), clock against the newest fetched commit of origin, and per board `requires`, write access to the repository, uncommitted work and the consistency of routines. Changes nothing, starts no model, no network without `--online`. `VERSION` is not raised: no card, routine or config key and no existing output changed.
- Repository (not part of the installed skill): `roadctl` 0.3.0, the run ledger (P5.1).
